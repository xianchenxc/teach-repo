Extensions、Skills 与 Coding Agent SDK

本课成果：你会用三种 PI 提供的扩展机制——Skills（知识注入）、Extensions（TypeScript 钩子与自定义工具）、Coding Agent SDK（把 pi 嵌进自己的应用）——并真实跑通一次「技能发现 → 扩展注册工具 → SDK 起会话」的完整链路。

已用 PI 0.84.3 真实运行
先预测

给 Agent 加「专长」和给 Agent 加「工具」，是同一件事吗？Skills 和 Extensions 各自解决什么问题？先写下答案。

1. Skills：把专长知识注入系统提示

Skill 是一个带 frontmatter 的 SKILL.md 文件，描述「模型在什么场景该加载这份知识」。它的 frontmatter 只有 description 是必须的——name 缺了会回退到父目录名，description 缺了则整条跳过。

---
name: browser-testing
description: Drive a headless browser to exercise and verify web UIs.
disable-model-invocation: false
---

# Browser Testing
Use Playwright to open pages, click, and assert.

发现规则（skills.ts）：从项目 .pi/skills/ 和用户 ~/.pi/agent/skills/ 递归扫描，遇到含 SKILL.md 的目录就当作一个 skill 根、不再下钻。name 需匹配 [a-z0-9-]+（小写、数字、连字符，≤64 字符）。

Skills 并不直接拼进每条消息，而是被 formatSkillsForPrompt 渲染成一段 XML，注入系统提示的 <available_skills> 块；模型按需用 read 工具去加载具体文件。设了 disable-model-invocation: true 的 skill 不进入该块，只能靠 /skill:name 显式触发。

<available_skills>
  <skill>
    <name>browser-testing</name>
    <description>Drive a headless browser to exercise and verify web UIs.</description>
    <location>/path/.pi/skills/browser-testing/SKILL.md</location>
  </skill>
</available_skills>

2. Extensions：TypeScript 钩子与自定义工具

Extension 是一个导出默认函数的 TypeScript 模块，函数签收一个 ExtensionAPI（pi）。它统一承载三类能力——事件钩子、自定义工具、斜杠命令：

import type { ExtensionAPI } from "@earendil-works/pi-coding-agent";

export default function (pi: ExtensionAPI) {
  // ① 事件钩子：观察/拦截 agent 生命周期
  pi.on("agent_start", () => console.log("starting"));
  pi.on("tool_call", (event) => {
    console.log(`tool: ${event.toolName}`);
    // 返回 { block: true, reason: "..." } 可拦截该工具
    return undefined;
  });

  // ② 注册自定义工具
  pi.registerTool({
    name: "shout",
    label: "Shout",
    description: "Return the given text uppercased.",
    parameters: Type.Object({ text: Type.String() }),
    execute: async (_id, { text }) => ({
      content: [{ type: "text", text: text.toUpperCase() }],
      details: { text },
    }),
  });

  // ③ 注册斜杠命令
  pi.registerCommand("mycommand", {
    description: "Do something",
    handler: async (args, ctx) => ctx.ui.notify(`got ${args}`),
  });
}

事件钩子覆盖完整生命周期：agent_start / turn_start / tool_call / tool_execution_start / tool_execution_end / agent_end / agent_settled 等，也能挂到更底层的 context、before_provider_headers、after_provider_response。扩展默认从 ~/.pi/agent/extensions/、<cwd>/.pi/extensions/、settings.json 的 extensions 数组发现，也可通过 extensionFactories 内联注册。

3. Coding Agent SDK：把 pi 嵌进自己的应用

上一课的 Agent 是低层运行时；pi 另提供一层 createAgentSession()，把模型、工具、技能、扩展、会话持久化打包成一个可直接驱动的会话。核心签名：

const { session, extensionsResult, modelFallbackMessage } =
  await createAgentSession({
    model,                 // 模型（缺省从 settings / 首个可用）
    modelRuntime,          // 模型与鉴权运行时
    thinkingLevel,         // off / low / medium / high
    tools: ["read", "shout"], // 工具名 allowlist（跨内置/扩展/自定义）
    customTools: [...],    // 额外的自定义工具
    resourceLoader,        // 技能/扩展/提示词/主题的资源加载器
    sessionManager,        // 会话持久化（inMemory / 落盘）
    settingsManager,
  });

session.subscribe((event) => { /* message_update, tool_execution_*, agent_settled */ });
await session.prompt("Shout the phrase.");

关键点：tools 是一个跨来源的 allowlist——它同时约束内置工具（read/bash/edit/write）、扩展工具、自定义工具。你注册了 shout 但没把它列进 tools，它就不会启用。

4. 完整实验：一次运行看三件事

脚本先在一个临时项目里放两个合法 SKILL.md 加一个「缺 description」的非法技能；再用 registerFauxProvider 注入脚本化模型（零 API 成本），内联注册一个扩展（记事件 + 注册 shout 工具），最后用 createAgentSession 起会话跑一轮。

本机真实输出 
[skills] browser-testing, code-review
[skill diagnostics] 1
[skills prompt]
<available_skills>
  <skill><name>browser-testing</name>...</skill>
  <skill><name>code-review</name>...</skill>
</available_skills>

[roles] user -> assistant -> toolResult -> assistant
[extension events] agent_start -> tool_call:shout -> agent_end:4
[provider calls] 2
[verify] all assertions passed

从输出读出三件事：

  • Skills 被正确发现与过滤：两个合法技能进列表，缺 description 的那个被跳过并产生 1 条诊断。
  • 扩展的钩子真实触发：agent_start → tool_call:shout → agent_end:4，与运行生命周期一致。
  • 扩展工具被 SDK 端到端调用：模型调用 shout，得到 user -> assistant -> toolResult -> assistant 的完整闭环。
