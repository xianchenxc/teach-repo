PI Agent · Capstone · 最终项目

代码库侦察 Agent

本课成果：把五课速通学到的能力拼成一个真实可运行的 Agent——给定一个仓库路径，用只读工具探查，产出一份结构化侦察报告并持久化到磁盘。

已用 PI 0.84.3 真实运行
任务

构建一个「代码库侦察 Agent」：它只能读（read / grep / find / ls），不能改任何项目文件；侦察结束后把报告用自定义工具 save-report 写入目标仓库的 RECON_REPORT.md。

1. 这份项目对应五课的哪些能力

能力来自在项目里的落点
Agent 运行时 + 工具 + 双 Turn 闭环第 2 课模型「读文件 → 出报告」的多轮流程
自定义工具 + throw 语义第 3 课save-report 工具（参数校验、执行、结果回填）
持久化思路第 4 课把侦察结果落到 RECON_REPORT.md
SDK + 跨来源 allowlist第 5 课createAgentSession + customTools + tools allowlist

2. 项目结构

project/codebase-recon/
├── src/recon-agent.ts   # 真实 Agent（read/grep/find/ls + save-report）
├── src/recon-demo.ts    # 零成本验证（脚本化 faux 模型）
├── package.json
└── README.md

两个入口：

  • npm run demo —— 零成本。用脚本化 faux 模型跑一遍相同接线，证明 SDK + 自定义工具 + 报告持久化真实可用，无需任何 API key。
  • npm start [仓库路径] —— 真实运行。需要已配置的 provider（ANTHROPIC_API_KEY / OPENAI_API_KEY 或 pi login），对真实仓库产出报告。

3. 零成本验证的真实输出（本机已跑通）

[roles] user -> assistant -> toolResult -> assistant
[provider calls] 2
[report exists] true
[report] # Recon Report | - purpose: toy project | - stack: TypeScript
[verify] all assertions passed

这条输出读出的关键：模型调用 save-report 工具 → 工具把报告写到磁盘（report exists: true）→ 结果回填（toolResult）→ 模型收尾。一次完整闭环。

4. 完成标准（definition of done）

  1. npm run demo 全绿，输出里的 [roles] 与 [report] 如上。
  2. （可选加分）配好 provider 后 npm start <一个真实仓库>，把生成的 RECON_REPORT.md 摘一段发来。

5. 现在动手

cd courses/pi-agent/project/codebase-recon
npm install --ignore-scripts
npm run demo
