先预测

一个最小但完整的工具 Agent，至少需要哪些运行时对象？先写下你的答案，再看下一节。

1. 五个必要部件

  1. Model / Provider：负责产生 assistant message；本实验使用官方 faux provider，不消耗 API。
  2. Tool schema：用 TypeBox 描述模型允许提交的参数。
  3. Tool execute：应用真正执行副作用或计算的函数。
  4. Agent：拥有 transcript、运行 loop、调度工具。
  5. Subscriber：观察流式文本、工具生命周期和 run 结束。
为什么用 Faux Provider？

它不是我们手写的 mock loop，而是 PI 官方 provider，仍然经过真实的 Models.streamSimple、Agent、参数校验、工具执行和事件系统。唯一被脚本化的是模型的两次回答，因此实验免费、确定、可重复。

2. 先定义工具的类型边界

const multiplyParameters = Type.Object({
  a: Type.Number(),
  b: Type.Number(),
});

const multiplyTool: AgentTool<typeof multiplyParameters> = {
  name: "multiply",
  label: "Multiply",
  description: "Multiply two numbers",
  parameters: multiplyParameters,
  execute: async (_id, { a, b }) => ({
    content: [{ type: "text", text: String(a * b) }],
    details: { a, b },
  }),
};

关键点：AgentTool<typeof multiplyParameters> 让 execute 中的 a、b 获得 schema 推导的类型。只写裸 AgentTool 会退化到 unknown 参数。

3. 注入模型与创建 Agent

const faux = fauxProvider();
faux.setResponses([
  fauxAssistantMessage(
    fauxToolCall("multiply", { a: 6, b: 7 }, { id: "call-1" }),
    { stopReason: "toolUse" },
  ),
  fauxAssistantMessage("6 × 7 = 42."),
]);

const models = createModels();
models.setProvider(faux.provider);

const agent = new Agent({
  initialState: {
    systemPrompt: "Use tools when needed, then answer concisely.",
    model: faux.getModel(),
    tools: [multiplyTool],
  },
  streamFn: models.streamSimple.bind(models),
});

Agent 不直接依赖某家 Provider；它只要求一个符合契约的 streamFn。这正是 PI 分层的实际价值。

4. 运行与观察

agent.subscribe((event) => {
  if (event.type === "message_update" &&
      event.assistantMessageEvent.type === "text_delta") {
    process.stdout.write(event.assistantMessageEvent.delta);
  }
});

await agent.prompt("What is 6 multiplied by 7?");
本机真实输出
[event] agent_start
[event] turn_start
[event] tool_execution_start
[event] tool_execution_end
[event] turn_end
[event] turn_start
6 × 7 = 42. The tool result has completed the loop.
[event] turn_end
[event] agent_end

[roles] user -> assistant -> toolResult -> assistant
[provider calls] 2

你应该从输出证明三件事

  • 两个 turn_start：模型被调用两次。
  • 中间出现 tool_execution_start/end：工具由 Runtime 执行。
  • roles 中存在 toolResult：结果被写回 transcript，第二轮模型可见。
